# Fix Icon Build — acceptance checklist

Each line is a check someone can run. Paths are on `main` (after PR #68). Only the PR's CI can
prove the macOS 26 items; run the local ones on the Mac.

## Requirement 1: CI runner

- [ ] `.github/workflows/ci.yml` job `app`: `runs-on: macos-26` (not `macos-latest`). Check: `grep -n "runs-on" .github/workflows/ci.yml`.
- [ ] `.github/workflows/ci.yml` job `app-pr`: `runs-on: macos-26`.
- [ ] Job `rust` (macOS lint/test): `macos-26` too, or left on `macos-latest` on purpose (optional, only if it costs nothing).
- [ ] `.github/actions/build-app/action.yml` prints `xcodebuild -version` and `sw_vers` before the build; the CI log of `app-pr` shows Xcode 26.x on macOS 26.
- [ ] The hand-picked `Xcode_26*` step in `build-app` (PR #68) is removed or still valid on the `macos-26` image (default Xcode 26.6).

## Requirement 2: compile step in `scripts/app.sh build()`

- [ ] `build()` runs `xcrun actool` on `crates/orch-app/icons/Orchestrator.icon` before the `tauri build` call, copied as `Icon.icon` with `--app-icon Icon` (same command as `icons/README.md`).
- [ ] Output goes to a gitignored path under `crates/orch-app/bundle/` (e.g. `bundle/icons/Assets.car`); `git check-ignore crates/orch-app/bundle/icons/Assets.car` succeeds (`.gitignore` already has `/crates/orch-app/bundle/`).
- [ ] `crates/orch-app/tauri.bundle.json` `bundle.macOS.files` maps `Resources/Assets.car` to that `bundle/...` path (no longer `icons/Assets.car`).
- [ ] When actool fails or writes no `Assets.car`, `build()` exits non-zero, prints actool's output and a one-line hint (Xcode >= 26 on macOS >= 26). Check: break the `.icon` path locally and run `scripts/app.sh build`.

## Requirement 3: committed binary removed

- [ ] `git ls-files crates/orch-app/icons/Assets.car` is empty.
- [ ] Still present: `crates/orch-app/Info.plist` (`CFBundleIconName` = `Icon`), the classic `icon.png` / `.icns` entries in `crates/orch-app/tauri.conf.json` (older macOS), `crates/orch-app/icons/liquid-glass/`, `crates/orch-app/icons/Orchestrator.icon`.
- [ ] No other file references `icons/Assets.car` (`git grep -n "icons/Assets.car"` only hits the new bundle path or docs saying it is generated).

## Requirement 4: post-build check in `scripts/app.sh build()`

- [ ] After `tauri build`, `build()` checks `Orchestrator.app/Contents/Resources/Assets.car` exists.
- [ ] It checks `Contents/Info.plist` has `CFBundleIconName = Icon` (e.g. `plutil -extract CFBundleIconName raw`).
- [ ] Either missing gives a non-zero exit with a clear message. Check: remove the `macOS.files` entry locally, build, expect failure.

## Requirement 5: docs

- [ ] `crates/orch-app/icons/README.md` says the icon is compiled at build time, needs Xcode 26+ on macOS 26+, and nothing is regenerated by hand (no manual `actool`/commit-the-`.car` steps left).
- [ ] The comment in `crates/orch-app/Info.plist` says the same (`CFBundleIconName` resolves in the compiled `Assets.car`).
- [ ] `docs/app/RUNNING.md`: yes, it lists requirements ("Needs: Rust (rustup), bun, Xcode command line tools, git >= 2.48, FiraCode Nerd Font…") under "Build and install". Update "Xcode command line tools" to "Xcode 26+ (full Xcode, for `actool`) on macOS 26+"; the "Updates" section names the `app` job runner ("macOS runner"), which can say `macos-26`.

## Requirement 6: local build

- [ ] On the user's Mac (Xcode 27 / macOS 27): `scripts/app.sh build` passes, then `scripts/app.sh install` (app quit first) installs it.
- [ ] The installed app shows the Liquid Glass icon in the Dock (user confirms).

## Acceptance

- [ ] `git ls-files crates/orch-app/icons/Assets.car` is empty on the PR branch.
- [ ] PR CI is green, including `app-pr` ("Build the app for the pull request"); its log shows the actool step compiling `Orchestrator.icon` on macOS 26 / Xcode 26.x.
- [ ] The `pr-build` artifact's `Orchestrator.app` has `Contents/Resources/Assets.car` and `Info.plist` `CFBundleIconName = Icon`.
- [ ] If actool still crashes on macOS 26: stop and follow the spec's fallback (lead asks the user before re-saving the `.icon` or keeping `Assets.car`).
