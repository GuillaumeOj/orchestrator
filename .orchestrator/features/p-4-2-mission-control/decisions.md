# P4.2 — Decisions

| # | Date | Decision | Why |
|---|---|---|---|
| D1 | 2026-10-29 | The P4 Penpot gate is split: **Part A** (shell, Mission control, session overlay, Inspector variants, keys) blocks front; **Part B** (every card kind and lifecycle, collapsed lines, rule card, morning line, J12 storyboard) is drawn in this phase too, but in parallel with front. Both are on `00 Cover` for the user's review before the PR. | SPEC §9.0 puts the whole gate before P4.2 UI work, but Part B only feeds P4.3; holding front on it would add a full design round to P4.2's critical path for no P4.2 screen. |
| D2 | 2026-10-29 | No chat column in P4.2 code; the right column stays the Inspector. The Inbox pane stays until P4.3. | The chat and cards are P4.3 (FR-1304/1305); an empty column would be a dead surface. |
| D3 | 2026-10-29 | Lanes map from the record's level: needs_you and error → Needs you (errors after the blocking ones); running → Running; waiting → Waiting on; queued → Queued; idle → a collapsed "Idle" line under the lanes; done → not a row (its outcomes are in Done today). | FR-1302 names five lanes; errors need the user; idle sessions are neither work nor waits but must stay reachable. |
| D4 | 2026-10-29 | A run is **one row** in the lane of the run's level; members are chips with their own waits. Queued members also get their own row in Queued. | FR-1302 "a team run is one row" and "the lane lists the whole queue"; the run level already ranks needs_you above running. |
| D5 | 2026-10-29 | A session opens as a tab in Mission control's group, in **watch mode**: Esc returns, ⏎ or a click takes over; after take-over every key goes to the PTY (Esc interrupts Claude Code as before) and leader `o` returns. | SPEC says Esc returns and §9.7 says every key goes to the PTY; Esc is Claude Code's interrupt. Watch-then-take-over keeps both and matches "panes are for watching or taking over". |
| D6 | 2026-10-29 | Row actions target one agent: the selected member chip (`h/l`), by default the run's blocker agent, else its lead. No team-level pause. | Every action already exists per agent (FR-903); a team pause is a new Governor action not asked for in P4.2. |
| D7 | 2026-10-29 | Queued rows read `queue {entry, position, tier, eta_ms, run_now}` from the attention record; the UI stops reading `app_state.agents[].queue_entry` for them. | Principle 10: Mission control renders `now` only; the cost in the binding window (FR-809) is the core's to compute. |
| D8 | 2026-10-29 | The project filter is a UI setting (`settings` key `mission`), multi-select, `null` = all; lane counts are the core's per-project counts summed over the filter. | FR-1302 "one, several or all; remembered"; no core logic depends on it. |
| D9 | 2026-10-29 | Overview columns (FR-901) move to row details (`space`) and the footer; the Overview pane type is removed, saved `overview` panes restore as `mission`. | FR-901 says Mission control keeps these columns in a row's details. |
| D10 | 2026-10-29 | `app.selection {kind, id}` (agent, run, decision) replaces `app.selectedAgent`; the focused agent pane still wins. | §3.5: the Inspector follows the selection in Mission control, and a run or decision is not an agent. |
